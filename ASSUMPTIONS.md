# CHARM flood-scoring PoC — assumptions register

Every result row in `benchmark_results` carries `measure` (`measured` | `extrapolated`) and `code_fidelity`
(`verbatim`, `verbatim+standin`, `verbatim+stub`, `verbatim+standin+reconstructed`). This file explains each assumption the numbers depend on.

| # | Assumption | Value used | Why / impact | How to retire it |
|---|---|---|---|---|
| A1 | Book of business size and shape | **1,000,000 CGIC Home policies** in the raw source schema (`item_id_m`, `latitudeinternal`, …), clustered around 40 Canadian population centres; fixed dirty-row rates (0.2% missing coords, 0.4% province centroids, 0.1% outside Canada, 0.3% bad TIV, 2% decimal deductibles, 1% unmapped dwelling style, 1% null foundation) | User direction; real book size not shared. Runtime scales with rows that survive filters (~97%) | Alex confirms row count; rerun T8 at that size |
| A2 | 50K-year event set | 50,000 years × 20 events/yr = **1,000,000 events per peril** (+1 coverage event per region); `return_period = 1/U` so ~5% pass their `>= 20` filter; heavy-tailed regional activity | User direction. Drives the merge output size (≈ events-per-region × policies) | Real `simulations2/*_simulation_events` row counts |
| A3 | Region polygons | **5,000 fluvial + 1,000 coastal** Voronoi cells over lon −141..−52 / lat 41..70, edges segmentized at 0.02° (~1.1M fluvial vertices, 12 MB .shp) | Real `can_flv_regions_v02.shp` / `can_cst_regions_v04.shp` not shareable; spatial-join cost depends on polygon count × vertex count | Run T4 on their shapefiles in LAB |
| A3b | Province polygons | **Synthetic rectangles** (13 provinces/territories, EPSG:3347, `PREABBR`). StatCan download is blocked from the PoC workspace | Province join is ~13 polygons, so it is cheap either way; real boundaries have far more vertices | Use `lpr_000a21a_e` from their Volume |
| A4 | `flood_model_serving` (PSS library) and its map assets | Stand-in with the same module paths/classes. **I/O shape assumed**: import-time `os.path.exists` on every asset; init reads 5 vector layers with GeoPandas + opens 24 tiles for bounds; each `predict()` opens and samples 2 rasters + 1–2 tiles and does 5 point-in-polygon lookups. Assets: 2 × 360 MB rasters, 16 + 8 multi-band depth tiles (~200 MB), vector layers 20K/5K defenses + 100K/30K flood zones + 2K exclusion (177 MB) → **≈1.1 GB total** | Real package/maps not accessible (user lacks Volume read). Absolute PSS ms/row will differ from theirs; **relative** effects (FUSE vs local disk, threads, partitions, scale-out) are what we claim | Paste `map_lookup.py` + `du -ah` of the maps folder; rebuild stand-in; rerun T1/T2a |
| A5 | Hosted PSS API (PR18 path) | In-process stub: **49 ms/call** median (VM: 48.7 s / 1k rows), lognormal jitter σ=0.3; optional 0.5% HTTP 503 | Network path from Azure to the API cannot be reproduced; throughput = concurrency / latency holds at any latency | Run the 1-cell latency probe in LAB |
| A6 | Loss aggregation | Stand-in: `loss = min(max(bdr×building + cdr×contents − deductible, 0), limit)` per event → per-year sum → AAL + max event loss per item | `LossPipeline` referenced but absent from the upload | Their `loss_pipeline` module |
| A7 | Cloud & node types | **Azure** (FEVM classic workspace, same SKUs CHARM uses: E2ds_v6, E8ds_v6, E4/E8as_v5, E48ds_v5). Serverless tests on the same Azure workspace | Removes the AWS→Azure mapping assumption | — |
| A8 | No long reproductions | Any size projected > 15 min (20 min for calibration) is **not run**; time is extrapolated with an affine fit `t = a + b·n` on the last two measured sizes and labelled `extrapolated` | User direction (time/cost) | Run the size if a number is contested |
| A9 | Reconstructed modules/fields | See `PATCHES.md` (pss_versions, config_flood_risks, schema/deductible fields, events paths, `to_geodataframe` alias, `GLOBAL` NameError) | Upload is a mid-refactor snapshot that does not import as-is | Alex shares a consistent commit |
| A10 | Cost basis | DBUs per run from `system.billing.usage` (by job run id) × Azure **Jobs Compute** list rate and × **All-Purpose** rate (their sheet uses All-Purpose $0.551/DBU ≈ CA$0.78) + Azure VM pay-as-you-go $/h (Canada Central list, captured in `90_results_summary`) | Customer discounts unknown; ratios between configurations are unaffected | Apply their negotiated rates |
| A11 | Cluster start-up | Reported separately (`setup_duration`), not inside stage timings. First start of a fresh workspace with Maven+PyPI libraries took **534 s** | Jobs pay this once per run; pools / serverless remove most of it | — |
